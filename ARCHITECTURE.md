# Архитектура Green Chat

## Общая схема

Приложение разделено на четыре уровня:

```text
ChatWorkspace
  ├─ feature UI components
  ├─ chat hooks (state, connection, polling)
  ├─ chat services (mapping, formatting, errors)
  └─ GREEN-API client
```

## Ответственность уровней

- `ChatWorkspace` собирает экран, связывает hooks и управляет открытием модального окна.
- `features/chat/components` содержит визуальные части чата: список, шапку, сообщения, composer и подключение.
- `features/chat/hooks` содержит состояние и сценарии: подключение, polling уведомлений и операции с чатами.
- `features/chat/services` содержит чистые функции без React: создание чата, форматирование идентификаторов и пользовательские ошибки.
- `lib/green-api` изолирует HTTP-контракты GREEN-API и преобразование входящих уведомлений.
- `components/ui` содержит переиспользуемые базовые элементы интерфейса.

## Поток входящего сообщения

1. `useNotificationPolling` получает уведомление через `receiveNotification`.
2. Уведомление передаётся в `useChatState`.
3. `mapIncomingMessage` приводит вложенный и плоский форматы к единой модели.
4. Состояние чатов обновляется, сообщение появляется в нужном диалоге.
5. Polling удаляет уведомление через `deleteNotification`.

## Работа с токеном

Токен вводится пользователем, используется только в памяти текущей вкладки и не сохраняется в исходниках или постоянном хранилище. URL и id инстанса можно задать через `.env` или форму подключения.

## Проверка качества

- `npm run test` — mapper и API-клиент.
- `npm run typecheck` — TypeScript.
- `npm run lint` — ESLint.
- `npm run build` — production-сборка.

Такая структура позволяет добавлять новые типы сообщений и функции чата без увеличения ответственности `ChatWorkspace` и без привязки бизнес-логики к JSX.
